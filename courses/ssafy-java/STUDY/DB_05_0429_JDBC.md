# JDBC — 자바에서 DB 와 대화하기

> **이 강의는 무엇인가**: 자바 표준 DB 연결 API `java.sql.*`. `Connection → PreparedStatement → ResultSet → close` 4단계로 SQL 실행하고 결과를 자바 객체로 변환.
> **왜 배우는가**: MyBatis·JPA·Spring Data 모두 결국 JDBC 위의 추상화. 그 밑바닥을 알아야 트랜잭션·커넥션 풀·예외 분류가 보임.

---

## 들어가기 전에

- **선수**: SELECT/DDL (1·3강), Servlet (Web Backend 1강).
- **드라이버**: MySQL 8 → `mysql-connector-j` 의존성 + classpath.

---

## 핵심 개념

### 1. 4단계 정형 코드

```java
public List<Board> findAll() throws SQLException {
    List<Board> list = new ArrayList<>();
    String sql = "SELECT id, title, content FROM boards ORDER BY id DESC";

    try (Connection con = DriverManager.getConnection(URL, USER, PW);  // ① 연결
         PreparedStatement ps = con.prepareStatement(sql);              // ② 준비
         ResultSet rs = ps.executeQuery()) {                            // ③ 실행

        while (rs.next()) {                                              // ④ 순회
            list.add(new Board(
                rs.getInt("id"),
                rs.getString("title"),
                rs.getString("content")));
        }
    }
    return list;
}
```

① TCP 연결 + 인증 → 비싸 → 재사용 필요.
② SQL 컴파일 + 파라미터 바인딩.
③ ResultSet = 결과 행 커서.
④ `rs.next()` 가 다음 행, false 면 끝.

### 2. URL · 드라이버

```java
String URL = "jdbc:mysql://localhost:3306/mydb"
           + "?useSSL=false&serverTimezone=Asia/Seoul"
           + "&useUnicode=true&characterEncoding=UTF-8";
```

한글 깨짐·시간 9시간 차이 사고의 90% 가 URL 인코딩/타임존 누락.

### 3. Statement vs PreparedStatement

```java
// ❌ Statement → SQL Injection
String sql = "SELECT * FROM users WHERE id = '" + userInput + "'";
Statement st = con.createStatement();
ResultSet rs = st.executeQuery(sql);

// ✅ PreparedStatement
String sql = "SELECT * FROM users WHERE id = ?";
PreparedStatement ps = con.prepareStatement(sql);
ps.setString(1, userInput);    // 자동 escape
ResultSet rs = ps.executeQuery();
```

**모든 SQL 은 PS 로** 가 원칙.

### 4. CRUD — executeQuery vs executeUpdate

```java
ResultSet rs = ps.executeQuery();    // SELECT
int affected = ps.executeUpdate();    // INSERT/UPDATE/DELETE
```

INSERT 자동 생성 ID:
```java
PreparedStatement ps = con.prepareStatement(
    "INSERT INTO boards (title) VALUES (?)",
    Statement.RETURN_GENERATED_KEYS);
ps.setString(1, "제목");
ps.executeUpdate();
try (ResultSet keys = ps.getGeneratedKeys()) {
    if (keys.next()) long newId = keys.getLong(1);
}
```

### 5. 트랜잭션

```java
con.setAutoCommit(false);          // 수동 모드
try {
    ps1.executeUpdate();            // 잔액 -1000
    ps2.executeUpdate();            // 잔액 +1000
    con.commit();
} catch (SQLException e) {
    con.rollback();
    throw e;
} finally {
    con.setAutoCommit(true);
    con.close();
}
```

기본 `autoCommit=true` (한 줄마다 즉시 commit). 송금 같은 작업은 false 로.

### 6. DAO 패턴

DB 접근 로직 분리. Servlet/Service 는 SQL 모르고, DAO 만 안다.

```java
public class BoardDao {
    public List<Board> findAll() { ... }
    public Board findById(long id) { ... }
    public long insert(Board b) { ... }
    public int update(Board b) { ... }
    public int delete(long id) { ... }
}
```

추후 Spring `@Repository` → MyBatis Mapper → JPA Repository 로 진화.

### 7. 커넥션 풀 (예고)

매 요청 `getConnection` 하면 TCP 비용으로 죽음. 실무는 **HikariCP** 같은 풀.

```java

cfg.setJdbcUrl(URL); cfg.setUsername(USER); cfg.setPassword(PW);
cfg.setMaximumPoolSize(10);
DataSource ds = new HikariDataSource(cfg);
try (Connection con = ds.getConnection(); ...) { ... }
```

Spring Boot 기본 HikariCP.

## 코드 깊게 들여다보기

게시판 페이지네이션 DAO:

```java
public List<Board> findPage(int page, int size) throws SQLException {
    String sql = """
        SELECT id, title, content, view_count, created_at
        FROM boards
        ORDER BY id DESC
        LIMIT ? OFFSET ?""";                              // ① 텍스트 블록

    List<Board> list = new ArrayList<>();
    try (Connection con = DriverManager.getConnection(URL, USER, PW);
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setInt(1, size);                              // ② 1-base
        ps.setInt(2, (page - 1) * size);

        try (ResultSet rs = ps.executeQuery()) {         // ③ RS 도 try
            while (rs.next()) {
                Board b = new Board();
                b.setId(rs.getLong("id"));
                b.setTitle(rs.getString("title"));
                b.setCreatedAt(
                    rs.getTimestamp("created_at").toLocalDateTime());  // ④
                list.add(b);
            }
        }
    }
    return list;
}
```

① JDK 15+ 텍스트 블록.
② PS 인덱스는 1-base — 까먹기 쉬움.
③ RS 도 try-with-resources 로 닫아야 누수 없음.
④ `Timestamp` → `LocalDateTime` 변환.

## 실전 패턴 / 자주 빠지는 함정

- ❌ `Statement` + 문자열 concat → SQL Injection.
- ❌ `con.close()` 안 함 → 커넥션 누수 → 풀 고갈.
  ✅ try-with-resources.
- ❌ `autoCommit=true` 로 트랜잭션 작업 → 중간 실패 시 부분 commit.
  ✅ `setAutoCommit(false)`.
- ❌ `rs.getString(1)` 인덱스 접근 → 컬럼 순서 바뀌면 깨짐.
  ✅ 컬럼명.
- ❌ DB 시간 ≠ 자바 시간 → 타임존.
  ✅ URL `serverTimezone=Asia/Seoul`.

## 다음 강의로 가기 전 자가점검

1. PS 가 Statement 대비 이점 2가지?
2. try-with-resources 가 누수 막는 원리?
3. INSERT 후 자동 생성 PK 받는 법?
4. 트랜잭션 수동 제어 시작점?

<details><summary>풀이</summary>

1. SQL Injection 방어, 컴파일된 SQL 재사용 성능.
2. try 종료 시 선언된 AutoCloseable 들을 선언 역순으로 close 자동 호출.
3. `Statement.RETURN_GENERATED_KEYS` 옵션 + `ps.getGeneratedKeys()`.
4. `con.setAutoCommit(false)` → 이후 `commit()`/`rollback()` 명시.

</details>
